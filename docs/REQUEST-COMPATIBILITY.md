# 请求与字段适配：v1.9.3

## 目标与层次

普通书源检测不调用 AI、不需要 API Key，不应把简单 URL 拼接一律标为动态脚本。但不能为提高检测通过数而运行上传的任意 JavaScript、原生宿主函数、浏览器脚本、登录流程或签名代码。

本版保留四个不同结论：结构合法、请求可解释、抽样 HTTP/字段验证、官方 App 实测。解释出了一个 URL 不意味着网站一定可访问；网站 HTTP 200 也不意味着配置正确。

## 共享实现

`converter/lib/staticScript.js` 使用固定版本 Acorn 解析完整语法树。仅对明确定义的数据操作实现解释，不使用 `eval`、`Function`、`vm` 或浏览器执行用户脚本。该实现随 `converter.bundle.js` 提供给浏览器，服务端也复用同一模块。

目前支持：局部变量、字符串/数字/布尔/空值、数据对象、条件语句与条件表达式、基础运算、字符串拼接/模板、关键词 URL 编码、十进制页码、Math.max/min、trim/charAt/substr/slice/indexOf 等有限字符串操作，以及少量经过逐一审核的 URL 正则模式。

读取范围只来自显式提供的 `config`、`params`、`result` 数据，不存在应用全局、文件、环境变量、网络或 DOM 权限。JSON 条目可用受限规则把 ID 拼成链接；HTML 字段只对唯一匹配节点应用受支持的后处理。多个节点需要如何拼接的 App 语义不能猜测。

拒绝的内容包括任意函数/回调、任意循环、未知变量、访问器、原型/构造器属性、动态属性名、展开调用、异步、导入、正则代码生成和任意正则模式。**未选择的分支以及 return 后面的语句同样需要通过审查。**

预算：脚本文本 10,000 字符，受审查节点 600，语法树深度 36，本地变量 64，解释步骤 1,800，单值字符串 24,000 字符；数据节点/集合也有边界。超出预算返回受限结果，不默默截断成成功。

## 已知旧版 URL 模板

`converter/lib/legacyLink.js` 只识别历史转换器输出的完整 URL 解析模板。它比较完整语法树，只允许一个静态兜底主机字面量不同；多余的语句、改动的循环或调用会使识别失败。匹配后调用受审查的内置 URL 解析实现，**不执行上传的循环代码**。

这用于兼容已维护源中的相对链接、目录分页和正文分页。它不提供通用 JS 循环执行能力，也不会绕过最终 URL 的域名/IP 安全检查。

## 只读搜索 POST

`server/request-plan.js` 只在搜索动作中接受一个可解释的请求对象，例如 `POST: true` 和 `httpParams`。它不是任意 HTTP 客户端。

要求：

- 目标必须为同站允许的公网域名，且为已列明的只读搜索路径 `/search[/]`、`/home/search[/]` 或 `/modules/article/search[we].php`；不带额外查询参数。
- 必须包含且仅包含一个当前测试关键词参数。可用字段名限定为 q、keyword、keywords、searchkey、key、wd、page、p、action、Submit。
- 额外控制字段仅支持规定的只读值，例如 `action=search`、空 Submit、有限数字页码。
- 不接受 Token、Cookie、认证、自定义签名或未知字段；不发送模型 Key、账户信息或用户自定义认证头。
- 表单按明确编码进行百分号编码，支持可无损表示的 UTF-8/GBK/GB2312。不可表示的字符直接报告限制。
- 301/302/303 依照 POST 转 GET 的规则丢弃表单；307/308 只允许原域名上的已批准搜索路径继续 POST。跨域、非搜索路径、内网和元数据目标一律不转发表单。

原始 Legado POST 仍应先转换成受检查的 XSGG 请求。仅给普通 URL 增加 POST 标记但没有可靠请求对象，不会被当作 GET 来验证。

## 请求参数和证据

保留旧的简单模板识别，以免关键词被二次编码。解释式中的 encodeURIComponent 按其 UTF-8 语义执行，不把它偷偷改成其他编码；页码依赖和未执行能力保留在报告中。

请求对象与动作声明的响应格式/编码发生不一致时报告受限，不忽略对象覆盖然后用错误的解析器声明成功。WebView、JSParser、解密和未知钩子也保持未验证。

报告展示 GET/POST、最终 URL、跳转、字符编码、表单字段名称、字段匹配、后处理是否完成和抽样范围。不会导出表单正文、Cookie、认证头值或 API Key。正文长度使用受支持后处理后的文本计算。

## 真实样本与限制

开发期间使用原维护的 15 条源做比较，**没有修改正式 ZIP/XBS/JSON 文件**。新的解释能力让原来停在请求识别阶段的多条源能够进入搜索、详情或完整静态阅读链；站点 403、超时、过大的目录以及未执行的元数据函数仍分别展示。

这轮没有增加每页 280KB、分页总量、页数或时间预算。起点/魔丸的大目录仍可能到达大小上限；可乐的未知令牌表单、菠萝猫的动态浏览器/签名流程不在支持范围内。

搜索无结果应结合关键词与网站响应判断。少量样本成功不能证明所有书籍、付费章节或官方 iOS App 全部正常。

## 测试

新增的离线回归在 `server/tests/static-script.test.js`，覆盖实际维护源中的请求模板、相对 URL、JSON ID、字段后处理、只读 POST、编码、重定向、未选择分支注入、访问器/原型访问、输入大小和语法预算、固定旧模板识别及未知循环拒绝。

浏览器共享实现的验证在 `tests/test-static-browser.cjs`；其余原转换器、服务端、队列和界面回归继续执行。实际网络测试使用 `tools/check-bundle-live.mjs` 独立记录，不能混入断网单元测试的通过数。
